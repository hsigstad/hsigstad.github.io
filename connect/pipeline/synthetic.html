Why a synthetic mirror

The real data lives on a locked-down RDP workstation at Bocconi. We can read, query, and run scripts there — but we can't develop there comfortably: no AI assistance, no interactive debugger, no git graph, no modern editor tooling. The only way out is a 25 MB zip export gated by manual approval. So the server is a bad place to iterate, and a necessary place to run.

The fix is to build a parallel local environment that looks identical to the server at the file-path level: same raw-data layout, same expected columns, same joins, same output paths. Scripts written locally against the synthetic data then run unchanged on the server.

Design goal. A labor-economist working on a new paper against the same Bocconi data sources (Base Trabalhista, RAIS, Registry, Brazil_family) gets a working local dev loop without touching the server. The synthetic generator is infrastructure, not throwaway code.

The pathmap translator

Pipeline scripts contain hardcoded absolute paths from the server. Rather than rewriting them with runtime configuration (invasive), pathmap.py rewrites the paths in-place and is run as a build step when bringing scripts local or shipping them back.

Server path
S:/Rais/2014/2_2014s.rds U:/secure.henrik.sigstad/justica G:/Brazil_family/data/A2_family_father.dta
pathmap.py
localize ↓  |  ↑ serverize
Local path
~/research/pipelines/bocconi/synthetic/S/Rais/2014/2_2014s.rds ~/research/pipelines/bocconi/justica ~/research/pipelines/bocconi/synthetic/G/Brazil_family/data/A2_family_father.dta

Idempotent — the same script runs either direction. Covers forward-slash (R, Python) and back-slash (Stata) variants, plus the old-tree bridges for parse/ outputs that aren't rebuilt yet.

End-to-end workflow

Each stage runs under SCons with explicit source/target dependencies — incremental, parallel, and inspectable. The last two pipelines also run on the server, against real data, with paths serverized.

python -m source.simulate.synthetic.generate

What this unlocks

  • Fast iteration. Script change → rerun the relevant stage with scons → see downstream outputs update, all locally with full tooling.
  • Safe refactors. Column renames and schema changes can be smoke-tested end-to-end before pushing to the server.
  • AI-assisted development. Claude Code can read, edit, and test the full pipeline without ever touching real data.
  • Estimator validation. Known embedded effects let us check that estimators recover the truth (open task).
  • Onboarding. A new collaborator clones, runs one command, and has a working pipeline in minutes.
  • Reusable infrastructure. Any future project on the same Bocconi sources inherits the synthetic generator for free.
