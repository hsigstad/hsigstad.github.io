Plan: Synthetic Raw Data for Full Pipeline Testing

Plan: Synthetic Raw Data for Full Pipeline Testing

Created: 2026-03-25

Context

We need synthetic data so we can develop/debug R/Stata/Python scripts locally with Claude Code, then transfer finalized scripts to the Bocconi secure server. The server has restricted exports (25MB .zip, output only, no primary data).

Approach: Synthesize all raw data sources at small scale

Generate a miniature but internally-consistent synthetic universe that mirrors the real raw data on the server. The full pipeline (justica, familia, economia -> connect) runs end-to-end on this synthetic data. This is a long-term investment: any new project using these same data sources gets synthetic data for free.

"Synthetic Brazil" scale:

  • ~1,000 people (judges, lawyers, litigants, relatives) with synthetic CPFs
  • Multiple foros of varying sizes: 1 large (20+ varas, passes randomization filters), 3-4 medium (5-10 varas), a few small (2-3 varas) -- realistic variation
  • ~50 judges, ~400 lawyers, ~50 with family connections to judges
  • ~100,000 labor court cases (5 years x ~20k/year, distributed across foros)
  • ~1,000 RAIS records/year (just the relevant people, not all of Brazil)
  • Known embedded treatment effects for estimator validation
  • Multiple TRTs to test cross-region variation

Steps

Step 1: Get current scripts from server

Export current source/ directories for connect, justica, and lstools. Status: submitted 2026-03-25, awaiting approval.

Step 2: Export metadata from server

Run an R/Stata script that extracts schemas and distributions from each raw dataset. For each raw file: column names, types, # rows, # unique values per column, value distributions for categoricals, numeric quantiles. Special focus on:

  • RAIS column names (these vary by year and are not fully visible from the extract scripts)
  • Exact .dta variable labels and value labels for the Stata files
  • The A2_family_father.dta / A2_family_mother.dta column structure (preference columns)
  • Brazil Owners file structure across snapshot dates

Step 3: Design the synthetic universe

Create a consistent set of synthetic people and institutions:

  • CPF pool: ~1000 people with names, birth dates, addresses
  • Family graph: ~50 judge-lawyer relative pairs (parents, spouses, siblings, cousins)
  • Court structure: multiple foros, ~25 varas, judge assignments
  • Law firms: ~50 CNPJs with partner/employee relationships
  • Case assignments: ~100k cases with random assignment to varas

The relationships must be internally consistent so that when the pipeline discovers "lawyer X is judge Y's cousin", it's because the family data actually encodes that path.

Step 4: Build the synthetic data generator

Generate all raw data files in the correct formats (.dta, .rds, .csv) at directory paths mirroring the server.

Output directory structure:

├── S/Base_Trabalhista_v2/pje/Base/Data/

├── data/adv/

├── data/usp/

Path adaptation: A config file or env var that maps S:/ -> synthetic/S/, etc.

Step 5: Run full pipeline on synthetic data

  1. Run justica pipeline: clean -> extract -> (skip parse) -> clean court-specific
  2. Run familia pipeline: parent.R, spouse.R
  3. Run connect pipeline: clean -> merge -> query -> table
  4. Validate: IPW estimator recovers embedded treatment effect

Step 6: Validate and iterate

  • Compare output schemas with real data schemas from Step 2
  • Fix any pipeline script failures (missing columns, type mismatches)
  • Verify table scripts produce well-formatted output

Critical files

  • justica/source/clean/TRT/proc.do -- main case cleaning (reads A0_laborcases.dta)
  • justica/source/extract/judge_rais.R -- RAIS extraction for judges
  • familia/source/parent.R, spouse.R -- family linkage
  • justica/source/extract/socio.do, escritorio.do -- business ownership
  • connect/bocconi/source/merge/merge.R -- main merge
  • connect/bocconi/source/query/gen_connection_dummies.R -- IPW weights
  • connect/bocconi/source/table/adv_connection_effects.R -- main analysis table

Export budget

  • Step 2: 1 export (metadata CSVs, <1MB)
  • Total: 2 exports, well within 25MB limit each
