    Datajud API

    Source

    • provider: CNJ (Conselho Nacional de Justica)
    • access: public Elasticsearch API (api-publica.datajud.cnj.jus.br)
    • authentication: API key via DATAJUD_APIKEY env var

    Coverage

    • geographic scope: all Brazilian tribunals (currently downloading TJSP)
    • population: all cases with assunto code 6226

    Unit of observation

    • individual court case (processo)

    Key variables

    • numeroProcesso: case number (NPU format)
    • classe: case type (codigo + nome)
    • assuntos: subject codes (one-to-many)
    • orgaoJulgador: court/judge division (codigo, nome, municipio IBGE)
    • grau: instance (1o grau, 2o grau, TR)
    • dataAjuizamento: filing date
    • dataHoraUltimaAtualizacao: last update timestamp

    Current counts (TJSP)

    • 339,797 cases downloaded
    • 317 unique assunto codes (cases can have multiple assuntos)
    • 106 unique case classes
    • 1,739 unique orgaos julgadores

    Pipeline

    • scrape: source/scrape/datajud.py -> build/scrape/datajud_tjsp.jsonl
    • clean: source/clean/datajud.py -> build/clean/datajud_tjsp_*.csv

    • population: cases with assunto "Inclusao Indevida em Cadastro de Inadimplentes"

    Receita Federal firm data (accessed inside BCB)

    Receita Federal datasets are accessed by Ramon inside the BCB environment. They are the source for firm-activity outcomes and for the plaintiff→firm linkage. Variable names below are from Ramon's Stata code (source/ra/do_regression_by_cnpj.do).

    Estabelecimentos (firm establishments)

    • source file: Receita/Janeiro 2025/estabelecimentos_all_codibge
    • unit: establishment (CNPJ branch)
    • key variables:
      • cnpj_basico: 8-digit CNPJ root (firm identifier)
      • situacao_cadastral: cadastral status code (e.g., "02" = active, "08" = closed)
      • data_situacao_cadastral: date of last status change (YMD string)
      • data_inicio_atividade: establishment opening date (YMD string)
      • razao_social: firm legal name
      • cod_ibge: IBGE municipality code

    Sócios (firm owners/partners)

    • source file: Receita/Janeiro 2025/socios_all.dta
    • unit: owner × firm
    • key variables:
      • cnpj_basico: firm identifier
      • cnpj_cpf: owner CPF (masked in some contexts)
      • nome: owner name
      • qualificacao_socio: role code (sócio, administrador, etc.)
      • data_entrada_sociedade: date joined

    Simples/MEI status

    • source file: Receita/Janeiro 2025/simples_data.dta
    • unit: firm
    • key variables:
      • cnpj_basico: firm identifier
      • Fields indicating opt-in dates and status for Simples Nacional and MEI regimes

    Constructed outcome variables (from source/ra/)

    Built in Ramon's stacked event-time panel, collapsed to (numero, year) or (cnpj_basico, year):

    Variable Definition Source
    active_firm 1 if year < closing year and year >= opening year situacao_cadastral, data_situacao_cadastral, data_inicio_atividade
    n_plants Count of active establishments in year Sum of active_firm across establishments
    new_firms 1 if establishment opened in this year data_inicio_atividade
    closed_firms 1 if establishment closed in this year situacao_cadastral == "08"
    mei 1 if firm is in MEI regime in year simples_data
    simples 1 if firm is in Simples Nacional in year simples_data
    won_case 1 if sentença ∈ {PROCEDENTE, PARCIALMENTE PROCEDENTE} Court sentence classification
    bias_magistrado Leave-one-out judge win rate (by magistrado) LOO mean of won_case
    n_plants_baseline Plants at t-1 (year before filing) n_plants at year == year_processo - 1

    Known issue: bias_magistrado is computed at the judge level, not the vara level. The principled instrument is vara-level leniency (see docs/methods.md §Open implementation questions).

    BCB-side panel construction

    Everything below is inferred from Ramon's .do files in references/ra_code/09042026/. It is not a Leonardo-approved data dictionary; the open questions at the end flag what still needs confirming.

    Raw input files (delivered by Leonardo to Ramon's BCB workspace)

    File pattern Source Vintage Years covered Identifier
    cnpj_v25112025_YYYY.csv SCR, CNPJ side 2025-11-25 2007–2024 mask_client (anonymised CNPJ)
    full_cpf_v25112025_YYYY.csv SCR, CPF side 2025-11-25 2007–2024 mask_client (anonymised CPF)
    masked_cpf_with_names_v06022026_cleaned_YYYY.csv SCR, CPF side + clear-text names for matching 2026-02-06 2007–2024 mask_client + nome

    One CSV per year per source; the April 2026 run uses the masked_cpf_with_names_v06022026_cleaned_* vintage for the CPF side (supersedes full_cpf_v25112025_*).

    Row-level unit in the raw files: (mask_client, numero, dmo_cd, mee_cd_mes) — a client × process × credit-modality × year-month observation.

    • mee_cd_mes is YYYYMM (monthly frequency).
    • dmo_cd is the credit-modality code; Ramon drops rows with dmo_cd >= 1900 before collapsing. [TBD: what this filter excludes — ask Leonardo.]
    • Each process (numero) can have multiple clients attached, and each client can appear in multiple processes; duplicates inside a (process, month) are additive (see 3_montarpainelcredito.do comments).

    Collapse logic (3_montarpainelcredito.do)

    For each year's CSV, two sequential collapses produce one row per (numero, year):

    1. collapse (sum) tot_contratos foc_vl_* foc_pc_* foc_qt_*, by(numero month)
    2. collapse (mean) ..., by(numero)

    Sums of values within a client-process-month, then averaged across the 12 months of the year. An alternative mask_client-level collapse is present in the same file but kept in stand-by.

    Yearly outputs are appended into painel_cnpj_processo.dta and painel_cpfnovo__processo.dta (the CPF panel built from the April 2026 vintage).

    Merge with court-side panel (4_pareamento.do)

    • Input from our side: painel_processos_judges.dta (~229,757 obs) — the process × year panel built by Mariani/Sigstad with plaintiff, judge/vara/comarca, and won_case already merged in. The linkage between court plaintiff and BCB mask_client is done upstream of this file, inside the BCB environment by Leonardo/Ramon.
    • Merge: merge 1:1 numero year against the CNPJ panel, then again against the CPF-novo panel. Unmatched BCB rows (_merge == 2) are dropped; unmatched court rows (_merge == 1) have their financial variables set to zero, on the read "no credit record = no credit."
    • Output: painel_processo_merge.dta, with foc_*_cnpj, foc_*_cpf, and tot_* (sum of both sides) outcome variants.

    Regression harness (5_rodandoregressoes.do, summary)

    Restricted to n_judges > 1. Fixed effects cnpj_basico, comarca_id # year_processo, year_processo # year; SE clustered at cnpj_basico. Three transforms per outcome (levels / log(x+1) / x > 0). Event study with ib5.id_dist_processo (t = −5 baseline, window ±5).

    Full naming schema in docs/reference/bcb_reports_index.md.
